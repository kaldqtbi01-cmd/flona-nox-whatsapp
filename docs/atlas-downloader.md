# تنزيل الوسائط عبر Atlas

## النطاق والأوامر

أضيف مسار تنزيل موحّد للروابط المباشرة من TikTok وInstagram وPinterest وFacebook وX وYouTube، باستخدام واجهات Atlas الخارجية. الاستخدام:

- `.atlasdl <رابط>` أو `.تنزيل_رابط <رابط>` لأي منصة ضمن النطاق.
- `.xdl <رابط>` لمنصة X.
- `.pindl <رابط>` لمنصة Pinterest.
- `.تنزيل_صوت <رابط YouTube>` أو `.ytmp3_atlas <رابط YouTube>` لصوت MP3.

أُضيفت الأوامر الجديدة إلى قائمة التحميلات. لم تُحذف أو تُحوّل معالجات FLONA القديمة في هذه الدفعة؛ هذا مسار إضافي صريح لتفادي تغيير أو تعطيل الأوامر القديمة قبل التحقق على نسخة التشغيل الفعلية.

## الاختبارات والقيود

التحقق المحلي شمل `node --check` للملفات المتغيرة و`npm test`. الاختبارات تتضمن استجابات API وهمية لكل واحدة من المنصات الست، رابطًا غير مدعوم، استجابة فاشلة، اختيار مسار YouTube الصوتي، والتحقق من payload المرسل إلى `sendMessage` وهمي.

هذه الاختبارات لا تتصل بواجهات التنزيل الحقيقية، ولا تثبت أن الواجهات الخارجية متاحة أو أن صيغة نتائجها ما زالت ثابتة. كما أنها لا تختبر إرسال WhatsApp فعليًا أو حسابًا حقيقيًا أو إصدار Baileys/إعدادات VPS. يلزم اختبار حي بعد التحديث على VPS برابط عام مناسب لكل منصة، والتحقق من تنزيل الوسائط وإرسالها فعلًا. لم يُجرَ هذا الاختبار الحي ضمن هذه الدفعة.

## التحديث على VPS

من مجلد المشروع:

```bash
cd /root/flona-nox-whatsapp
git pull origin main
npm install
pm2 restart flona
pm2 save
```

ثم جرّب في المحادثة مثلًا `.atlasdl <رابط عام>`، وبالنسبة إلى الصوت `.تنزيل_صوت <رابط YouTube>`. إذا فشلت منصة بعينها، احتفظ برسالة الخطأ وافحص سجل PM2؛ قد تكون واجهة الطرف الثالث متوقفة أو غيّرت استجابتها.
